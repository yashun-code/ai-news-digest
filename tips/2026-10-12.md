## Worktreeの基本：複数ブランチを同時に作業

Gitの `git worktree` コマンドで、1つのリポジトリから複数の独立した作業ツリーを作成できます。メインブランチで作業しながら、別フォルダで機能ブランチを同時に編集できるので、コンテキスト切り替えのストレスが減ります。

- kind: lesson
- term: Worktree＝リポジトリから作られた独立した作業フォルダ。各フォルダは異なるブランチをチェックアウトできる
- try: git worktreeを使って、mainブランチの横にfeature-ブランチの作業フォルダを作ってください
- source: https://docs.claude.com/ja/docs/claude-code

## Claude Codeでの隔離実行

Claude CodeのAgent tool設定で `isolation: 'worktree'` を指定すると、エージェントを隔離したworktree上で実行させられます。これによりエージェントの操作が本体のコードに影響しません。

- kind: skill
- term: isolation＝エージェントが作業する環境を分離する。worktreeを使うと副作用が起きにくい
- try: Claude Codeでエージェントを実行する際、worktreeでの隔離実行の設定を確認してください
- source: https://docs.claude.com/ja/docs/claude-code

## 並行開発のワークフロー

ターミナルで `git worktree add ../feature-x feature-x-branch` を実行すると、親フォルダに `feature-x` フォルダが作られ、そこで `feature-x-branch` が自動チェックアウトされます。別ウィンドウやエディタでそのフォルダを開けば、同時に複数ブランチを編集できます。

- kind: md
- term: 並行開発＝複数の機能やバグ修正を同じ時間帯に異なるブランチで進める
- try: git worktree add コマンドを試して、新しいブランチ用の作業フォルダを作成してください
- source: https://docs.claude.com/ja/docs/claude-code

## Worktreeの削除と管理

作業が終わったら `git worktree remove ../feature-x` でworktreeを削除します。`git worktree list` で現在のworktree一覧を確認できます。

- kind: md
- term: Worktreeのライフサイクル＝作成→編集→削除の流れで、プロジェクト管理を効率化
- try: git worktree list コマンドで、プロジェクトの全worktreeを確認してください
- source: https://docs.claude.com/ja/docs/claude-code
